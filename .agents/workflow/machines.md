# 机器使用

## 项目根目录

| 用途 | 主机与绝对路径 |
|---|---|
| Agent 工作目录（`AGENTS.md`、`.agents/`） | 【首次使用时确认：Agent 在哪台机器、哪个目录运行并维护文档？】 |
| 代码根目录 | 【首次使用时确认：源码在哪台机器、哪个目录？与 Agent 工作目录相同时填“同上”；多台机器分别列出。】 |

**本地运行 Agent、远端存放代码时**，在本地工作目录更新文档，通过下方 SSH 入口到对应的远端代码根目录修改和运行代码。不能默认当前工作目录就是源码目录。

## 本仓库可用机器

【首次使用时确认：本项目可以使用哪些机器？请列出机器名和 SSH 入口。只用本机时填写“仅本机”。】

“所有机器”仅指本节列出的机器。分配设备时不得抢占正在运行的任务。

- **正式训练**使用研究者为本次任务指定的机器。先看 [CURRENT](../CURRENT.md) 中的有效分配，尚未指定时再问。
- **临时测试**由 Agent 从清单中选用空闲资源，无需另行询问。

## 设备与职责

- **训练和评测是否联跑，由研究者决定。** 只交办训练时，Agent 可以提议联跑，未经确认不能自行启动评测。
- 分侧执行时，训练侧交接权重、接口和评测要求。特殊硬件要求写入对应 benchmark 的方案。

## 环境、存储与传输

**项目依赖使用独立 Conda 环境。** 原生库安装到该环境或局部解包至工作区。

- 安装和运行均设置 `PYTHONNOUSERSITE=1`。将此值写入 Conda 环境和运行入口。
- 安装 Python 包时设置 `PIP_USER=0`，使用目标环境的 `python -m pip`，禁止 `--user` 安装。

跨机交接数据和 checkpoint 时，注明主机和路径，传输成功即可，不要检验sha256。

## 网络与代理

下载及 Git 远端操作只在命令的子 shell 中切换代理。禁止使用 `~/.codex/.env` 中的服务代理，也不得读取或输出其凭据。

1. 清空继承的所有大小写代理变量，调用 `~/.bashrc` 中的 `proxy_on`、`enableProxy` 或同类函数，在同一子 shell 内执行网络操作。
2. 代理函数不可用或失败时，再次清空代理变量，以 `curl www.google.com` 测试直连。成功后在同一子 shell 内直连，失败则停止并报告。
