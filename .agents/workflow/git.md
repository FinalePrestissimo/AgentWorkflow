# Git 交付与同步

## 仓库范围与默认交付

【首次使用时确认：该仓库用于同步和交付的私有 Git remote 和分支是什么？无需同步时填“无远端同步”。文档与代码分属不同仓库时分别填写。】

按[项目根目录](machines.md#项目根目录)定位本次任务涉及的仓库，在它所在的主机和目录执行 Git 操作。只改本地文档时无需同步远端代码仓库。非 Git 目录直接在原处工作；缺少 Git remote 或 upstream 时不自行猜测。

首次使用或更换远端时，确认账号、仓库和实际私有状态。远端操作遵循[网络与代理](machines.md#网络与代理)。

## 任务开始前同步

每次开工或接续，先判断更新会不会影响已有改动或正在运行的任务。会受影响时保留原工作区，在独立工作区同步。

有约定远端时执行 `git pull --ff-only`。若分支已分叉，保留双方提交并合并。同步成功后再读取最新上下文。禁止用 `git reset --hard`、`git clean -fd` 或强制 push 清理或同步。

## 改动与提交

**默认提交并推送到已确认的私有远端。** 研究者另有指示时按其要求交付。

审阅本次差异，只暂存本任务的代码、配置和文档。凭据、数据、checkpoint 和大型运行产物留在 Git 之外。

`pull`、`commit` 或 `push` 成功后，无需额外 `fetch` 或比对 SHA 来确认成功。

## 跨侧同步

评测侧使用交接时指定的训练版本。另有评测修复时，在运行产物中分别记录训练和评测版本，并将修复同步回安全的训练工作区。暂时无法同步时在 [CURRENT](../CURRENT.md) 留下接续点。
